================================================================================
SECTION 1: DESIGN TOKENS & FOUNDATION
================================================================================

These are the core visual primitives that define the look and feel of every
screen in the application. All values are Tailwind CSS utility classes that
can be used directly in a React/Tailwind MERN project.

--------------------------------------------------------------------------------
1.1 COLOR PALETTE
--------------------------------------------------------------------------------

PRIMARY BLUE
  Classes:  blue-600 (#2563EB), blue-700 (#1D4ED8), blue-50 (#EFF6FF)
  Usage:    Primary action buttons, active navigation links, focus rings,
            info badges, sidebar active state highlight, notification accents.
            This is the dominant brand color throughout the interface.

ACCENT GREEN
  Classes:  green-600 (#16A34A), green-500 (#22C55E), green-50 (#F0FDF4)
  Usage:    Login "Sign in" CTA button, success flash messages, completed
            status badges, active task counts, confirmation states.
            Used as the secondary action color for positive outcomes.

DANGER RED
  Classes:  red-500 (#EF4444), red-600 (#DC2626), red-50 (#FEF2F2)
  Usage:    Error alerts, delete buttons, urgent priority indicators,
            overdue task counts, unassigned task queue accent bar,
            notification badges on the bell icon.

WARNING AMBER
  Classes:  amber-500 (#F59E0B), amber-600 (#D97706), amber-100 (#FEF3C7)
  Usage:    Pending status badges, "Needs Clarification" states,
            "Action Needed" stat card numbers, medium-priority indicators.

PURPLE
  Classes:  purple-700 (#7E22CE), purple-100 (#F3E8FF), purple-50 (#FAF5FF)
  Usage:    Admin role badges, "Total Tasks" stat card number,
            report chart accent color. Reserved for admin/authority contexts.

TEAL
  Classes:  teal-600 (#0D9488), teal-50 (#F0FDFA)
  Usage:    "Completed Tasks" stat card in reports page only.
            Niche accent for differentiating completed metrics.

PAGE BACKGROUND
  Value:    #f4f7f6 (applied to <body>)
  Usage:    The overall application background. A very light grayish-green
            that provides contrast against white card surfaces.

SURFACE WHITE
  Value:    white (#FFFFFF)
  Usage:    All cards, tables, modals, sidebar, header, dropdowns.
            Every content container sits on a white surface.

BORDER COLOR
  Classes:  border-gray-100 (#F3F4F6), divide-gray-50 (#F9FAFB)
  Usage:    Card borders, table row dividers, section separators.
            Extremely subtle — almost invisible against white.

TEXT COLORS
  Primary:    gray-800 (#1F2937), gray-900 (#111827) — headings, titles
  Secondary:  gray-500 (#6B7280), gray-600 (#4B5563) — body text, subtitles
  Muted:      gray-400 (#9CA3AF) — labels, timestamps, placeholder text
  Link:       blue-600 → blue-700 on hover — all clickable text links

--------------------------------------------------------------------------------
1.2 TYPOGRAPHY
--------------------------------------------------------------------------------

PRIMARY FONT: Figtree
  Weights loaded: 400, 500, 600, 700, 900
  Source:     https://fonts.bunny.net/css?family=figtree:400,500,600
  Applied:    font-sans (set as default sans in tailwind.config.js)
  Usage:     All body text, buttons, labels, navigation items.

SECONDARY FONTS (available but rarely used):
  Inter    — font-inter, loaded via Google Fonts, available for alternatives
  Poppins  — font-poppins, loaded via Google Fonts, available for alternatives
  Roboto   — font-roboto, loaded via Google Fonts, available for alternatives

HEADING STYLE (Page Titles):
  Classes:  text-3xl font-black text-gray-800 tracking-tight
  Example:  "Request Directory", "Operational Tasks", "ICT Calendar"
  Desc:     Extra-large, extra-bold, tight letter-spacing for a modern,
            authoritative look. Always paired with a subtitle below.

SUBTITLE STYLE (Page Descriptions):
  Classes:  text-sm text-gray-500 mt-1 font-medium
  Example:  "Manage and monitor all ICT service requests."
  Desc:     Small, medium-weight gray text placed directly under the title.

SECTION LABEL STYLE (Card/Table Headers):
  Classes:  text-[10px] font-bold text-gray-400 uppercase tracking-widest
  Example:  "TOTAL REQUESTS", "PENDING APPROVALS", "REF CODE"
  Desc:     Tiny, bold, all-caps with wide letter-spacing. Used for column
            headers in tables and metric labels on stat cards.

CARD TITLE STYLE:
  Classes:  text-lg font-bold text-gray-800
  Example:  "Recent Requests", "My Active Tasks"
  Desc:     Used for section/panel headings inside card headers.

BODY TEXT:
  Classes:  text-sm font-medium/semibold text-gray-600/700/800
  Desc:     Standard body content. Font weight varies: semibold for emphasis
            (names, titles), medium for descriptions.

1.5 SHADOW SYSTEM
--------------------------------------------------------------------------------

CARDS (Subtle):
  Value:  shadow-[0_2px_10px_rgba(0,0,0,0.04)]
  Desc:   Nearly invisible shadow that lifts cards slightly off the
          background. Used on ALL white content containers.

PRIMARY BUTTONS (Elevated):
  Value:  shadow-[0_4px_14px_rgba(37,99,235,0.39)]
  Desc:   Blue-tinted shadow beneath primary action buttons. Creates a
          floating, clickable appearance.

LOGIN CARD (Dramatic):
  Value:  shadow-[0_20px_50px_rgba(0,0,0,0.1)]
  Desc:   Large, soft shadow for the login dual-card. Gives a floating
          modal-like appearance over the blurred background.

MODALS & DROPDOWNS:
  Value:  shadow-2xl
  Desc:   Maximum shadow for overlays that sit above all other content.

SIDEBAR:
  Value:  shadow-[4px_0_24px_rgba(0,0,0,0.02)]
  Desc:   Right-side-only subtle shadow that separates sidebar from content.

HEADER:
  Value:  shadow-[0_2px_10px_rgba(0,0,0,0.02)]
  Desc:   Bottom shadow on the top header bar. Extremely subtle.

--------------------------------------------------------------------------------
1.6 TRANSITIONS & ANIMATIONS
--------------------------------------------------------------------------------

COLOR TRANSITIONS:
  Classes:  transition-colors (on most interactive elements)
  Duration: Tailwind default (150ms)

TRANSFORM TRANSITIONS:
  Classes:  transition-transform duration-300 (sidebar slide, drawer)
  Classes:  transition-all duration-300 (backdrops, toasts)

LOGIN CARD ENTRANCE:
  slide-in-left:  0.8s cubic-bezier(0.23, 1, 0.32, 1), translateX(-50px) → 0
  slide-in-right: 0.8s cubic-bezier(0.23, 1, 0.32, 1) 0.2s delay, translateX(50px) → 0
  Desc:           The two halves of the login card animate in from opposite
                  sides with a smooth elastic easing and staggered timing.

TOAST NOTIFICATIONS:
  Enter: translate-y-full opacity-0 → translate-y-0 opacity-100 (300ms)
  Exit:  translate-y-0 opacity-100 → translate-y-full opacity-0 (300ms)
  Auto-dismiss after 5 seconds.

DRAWER SLIDE:
  Closed: translate-x-full (off-screen right)
  Open:   translate-x-0 (fully visible)
  Duration: 300ms ease-in-out

MOBILE SIDEBAR:
  Closed: -translate-x-full (off-screen left)
  Open:   translate-x-0 (fully visible)
  Duration: 300ms ease-in-out
  Backdrop: opacity-0 → opacity-100 with backdrop-blur-sm

NOTIFICATION PULSE (unread dot):
  Classes:  animate-ping on a bg-blue-400 span behind a solid bg-blue-500 dot
  Desc:     Creates a radar-pulse effect to draw attention to unread items.

SECTION 5: INTERACTIVE BEHAVIOR PATTERNS
================================================================================

--------------------------------------------------------------------------------
5.1 NOTIFICATION POLLING (Real-time Updates)
--------------------------------------------------------------------------------
  Interval:   10 seconds (setInterval)
  Endpoint:   GET /notifications/poll?since={ISO timestamp}
  On new notifications:
    1. Show toast for each (color based on type: error for reject/blocked,
       success for approve/complete, info for others)
    2. Update lastPollTime to latest notification's created_at
    3. Refresh dropdown if currently open
    4. Update badge count
  Time display: Custom timeAgo() function — "Just now", "Nm ago", "Nh ago", "Nd ago"

--------------------------------------------------------------------------------
5.2 DRAWER (Detail Panel)
--------------------------------------------------------------------------------
  Open:       openDrawer(type, id) → fetches GET /{type}s/{id}/partial
              Removes translate-x-full class, shows backdrop
  Close:      closeDrawer() → adds translate-x-full, hides backdrop
  Loading:    Shows "Loading details..." placeholder
  Error:      Shows warning icon + error message + retry suggestion
  Usage:      Request "Review", Task "View", Calendar event click

--------------------------------------------------------------------------------
5.3 MOBILE SIDEBAR
--------------------------------------------------------------------------------
  Toggle:     toggleMobileSidebar()
  Open:       Removes -translate-x-full from sidebar, shows backdrop with opacity transition
  Close:      Adds -translate-x-full, fades backdrop, hides after 300ms
  Backdrop:   bg-gray-900/50 backdrop-blur-sm, click to close

--------------------------------------------------------------------------------
5.4 DROPDOWN POSITIONING (Task Assignment)
--------------------------------------------------------------------------------
  Strategy:   Fixed positioning calculated from button's getBoundingClientRect()
  Position:   Top = button bottom + 4px, Left = button left
  Overflow:   If dropdown would go off-screen right, repositions to window edge - 16px
  Width:      w-64 (256px fixed)
  Close:      Click outside detection via document click listener
  Single:     Only one dropdown open at a time (closes previous)

--------------------------------------------------------------------------------
5.5 CALENDAR RENDERING
--------------------------------------------------------------------------------
  Approach:   Pure JavaScript DOM manipulation (no library)
  Data:       Events passed as JSON array from server
  Rendering:  Loops through month days, filters events by date overlap
  Multi-day:  Connected visual spanning with border-radius and margin tricks
  Hover sync: All segments of same event highlight together via data-event-id
  Navigation: prev/next/today buttons modify currentDate and re-render
